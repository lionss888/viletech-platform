────────────────────────────────────────
Зачем этот файл

Зафиксировать узкий объём кода, когда главная приёмка схемы и решения пройдена.
Пока «ок» нет — в кабинетах и домене ничего не меняем.

────────────────────────────────────────
Делаем (узко)

Продуктовые подсказки / help: «какой рычаг выбрать» для менеджера (guided next step / короткий текст), согласованный с текст-для-менеджмента.txt и схемой-устройства.txt.
При необходимости — синхронизация формулировок с каталогом сценариев и заметками согласования.
Цель: менеджер понимает сборку из рычагов, не ждёт BPM-редактора.

────────────────────────────────────────
Не делаем в этой программе

- Свободный граф статусов / BPM-редактор этапов.
- Выключение обязательных gates из админки вопреки политике.
- Передача process-roles менеджеру сделки.
- Runtime-автоматизация статусов из vedy_bot.
- Новый участник-актор с переходами статусов.

────────────────────────────────────────
Слои включить перед кодом

Минимум: Docs / notify (если закрываем волну текстом в продукте).
Если трогаем кабинет: UI / IA + Компонент / FE + Unit.
Если меняется journey CTA: E2E / journey (+ ci-pr-pilot по path-filter).
Домен / API — только если без смены контракта нельзя обойтись; по умолчанию не трогаем статусную машину.

QG

Главная приёмка текстов/схемы остаётся человеческой («ок»).
