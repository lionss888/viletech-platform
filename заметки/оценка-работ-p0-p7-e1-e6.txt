## 1. Что входило в scope

Две последовательные программы:

1) Lifecycle BDUI (P0–P7)
   - матрица role×status→actions, seed 5 ролей ВИ
   - User wizard → ICO → ECO → Manager → Provider → close → COMPLETED
   - ветки: corrections, cancel, postpay

2) UI readiness (E1–E6)
   - one-click launch, реальные PDF upload
   - happy-path и ветки только через UI
   - кабинеты 5 ролей, документы/manager attach
   - DoD: оператор без Swagger/curl

Вне scope (не оценивать как «долг» этих планов):
refund, Bank API, субагент/услуги, Diadoc, Admin/Superadmin, pixel-perfect Figma.

## 6. Как использовать для следующих оценок

1. Брать baseline из §3 (чел·дни) на похожий кусок: «роль × статусы × CTA + schema + unit + ручной gate».
2. Если снова agent-assisted: ожидать wall-clock порядка часов на этап P-класса, но закладывать:
   - время на планирование и разбиение планов;
   - ручной QA / DoD (не схлопывается в минуты кода);
   - рассинхрон статусов plan YAML vs LIFECYCLE.
3. Не смешивать в одну оценку: доменный API/state machine vs BDUI-обвязка vs UI polish.
4. Для UI readiness отдельно учитывать операторский прогон (E3/E4/E6 DoD) — в факте 25.08 он частично ещё открыт.
5. При оценке нового эпика фиксировать заранее: число ролей, число статусов/переходов, file-upload, ветки, нужен ли one-click launch.
