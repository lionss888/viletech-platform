## DoD

1. `make -C vdp check-env-parity`
2. Unit затронутого слоя
3. Если срез про мастер заявки / extraction / Docling / OCR UI: `make -C vdp ocr-path-gate` (Local QG «Путь распознавания») **до** Acceptance руками клиента. Зелёные precommit / лестница не заменяют этот шаг.
4. Имя gate (ровно одно): `ci-pr` | `ci-pr-pilot` | `ci-main` (новый e2e вне smoke → `ci-main`)
5. Acceptance пройден на localhost
6. (если в scope) Acceptance на alpha после «До alpha» в Local QG

Не пушить поверх уже идущего длинного `ci-pr-pilot` / `ci-main` без крайней нужды.

## Срез дня

Сегодня: только этот срез. Если не укладывается в ≤ 24 ч с gate — нарезать дальше до исполнения.

### Выбор gate (кратко)

| Что меняли | Gate / кнопка Local QG |
|---|---|
| Без UI journey, без ladder paths | `ci-pr` или `ci-pr-fast` (без браузера) |
| Мастер / extraction / Docling / OCR UI | сначала `ocr-path-gate` — «Путь распознавания»; ручной UAT только после зелёного |
| ActionPanel / status-matrix / form-payment / `@pilot-matrix` / e2e только smoke | `ci-pr-pilot` — «лестница» |
| `vdp/fe/e2e/**` вне узкого smoke | `ci-main` — «Main push (полный браузер)» |
| Неясно | Local QG → «Подскажи проверку» |

## Онбординг специалиста

Сделай по порядку один раз на машине. Команды — из каталога `vdp`, если не сказано иначе.

1. Прочитай эталон: [ориентир-скорости-запросов-заказчика-2026-09-21.md](ориентир-скорости-запросов-заказчика-2026-09-21.md). Единица готовности — запрос/срез и Acceptance, не строки кода.
2. Версии среды: канон в `vdp/docs/development/environment-requirements.md`. Проверка: `make -C vdp check-env-parity`. При расхождении Node — `nvm use` / `mise` по `.nvmrc` в `vdp/fe`.
3. Git hooks: `make -C vdp install-git-hooks`. Commit = короткий слой; Push = path-aware gate (не обходи `SKIP_PREPUSH_GATE=1` без причины).
4. Открой в Cursor canvas `local-qg.canvas.tsx` (Local QG). Кнопки = проверки; команды make знать не обязательно.
5. Подними локальную среду при работе с кабинетом: Local QG «Поднять среду» / `make compose-up`. FE deps в Docker — только после явного «да» (`compose-fe-refresh`).
6. Перед работой: план среза по шаблону выше (Запрос, Acceptance, DoD с именем gate).
7. Перед commit: Local QG «Перед коммитом». Перед push: «Подскажи проверку» → нужная кнопка gate из DoD. «Готово» только после зелёной кнопки DoD и Acceptance.
8. После merge: Local QG «До alpha» — убедиться, что выкат прошёл или что блокирует. Секреты notify: `make check-deploy-secrets` / `vdp/docs/development/local-qg-deploy-secrets.md`.
9. Замер недели: заполняй строку в [замер-lead-time-неделя-2026-09-22.md](замер-lead-time-неделя-2026-09-22.md) после закрытия среза.

Если что-то красное — не утверждай готовность; смотри вывод Local QG простым языком и чини срез, не следующий запрос.
