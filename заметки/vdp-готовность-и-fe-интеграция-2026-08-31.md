# ЧАСТЬ A. FE↔API — приоритет №1

## A.1. Интеграцию сделали?

**Нет — в коде `vdp/fe` интеграции с core нет.**

Что есть (инфраструктура, не интеграция):

- `vdp/fe/vite.config.ts` — proxy `/api` → `http://localhost:8080` (env `VDP_API_PROXY_TARGET`).
- Документация описывает **целевой** app-контур: `vdp/docs/architecture/app-vs-demo.md`, `vdp/docs/api/overview.md`.

Что есть в коде (демо):

- `vdp/fe/src/lib/ved/store.tsx` — состояние в `localStorage` (`ved-demo-state-v2`).
- `vdp/fe/src/lib/ved/mock.ts` — seed-данные.
- Все маршруты (`/login`, `/forms`, `/dashboard`, …) используют `useVed()`, не HTTP.
- `login.tsx` — проверка пароля по `ROLES` локально, без `POST /api/v1/auth/login`.
- `ActionPanel.tsx` → `applyAction()` меняет статус **только в localStorage**.
- `forms.new.tsx` → `createForm()` пишет в mock, не `POST /api/v1/forms`.

Папки `/demo/*` в роутере **нет** — отдельный demo-контур из `app-vs-demo.md` **не реализован**; весь текущий UI = демо.

Grep по `fe/src`: нет `api/v1`, `vdp-auth`, клиента API (кроме комментария в vite.config).

## A.2. Почему казалось, что интеграция есть

1. Доки (`app-vs-demo.md`, `api/overview.md`, `testing.md`) описывают **platform-store bridge** и JWT — это **план/контракт**, не код в `fe/src`.
2. Proxy настроен — браузер *может* ходить на core, но **ни один компонент этого не делает**.
3. Backend готов: auth, forms CRUD, actions, files, nest-parity routes — всё тестируется в Go `compose-e2e`.

## A.3. Расхождение action id (важно для оценки)

| Слой | Id действий | Пример |
|------|-------------|--------|
| FE `actions.ts` | UI-идентификаторы | `accept_form`, `ico_form_start`, `mgr_assign_provider` |
| Core `formpayment.Action` | доменные | `submit`, `ico_start`, + отдельные endpoint'ы |

Маппинг `accept_form` → `submit` **в репозитории не реализован** (нет `platform-store`, нет `action-bridge.test` в fe).

Многие manager-действия — не один `POST .../actions/{action}`, а:

- `POST /api/v1/forms/{id}/agent`
- `POST /api/v1/forms/{id}/provider`
- `POST /api/v1/forms/{id}/rate`, `/commission`
- `POST /api/v1/manager/form-payment/{id}/contract/manual-attach`
- Nest-parity `PUT /api/v1/{role}/form-payment/{id}/...`
- `POST /api/v1/file-store/upload` + attach к form

## A.4. Расхождение моделей данных

**API `formpayment.Form`** (snake_case, поля домена):

- `organization_id`, `invoice_amount`, `rate`, `commission`, `docs_json`, `channel`, …
- Нет: `number`, `ownerName`, `managerName`, `documents[]`, `timeline[]`, `amountMinor`, `condition`

**FE `PaymentForm`** (UI-модель из mock):

- `number`, `amountMinor`, `condition`, `documents`, `timeline`, display names

Нужен **mapper API → UI** (или смена UI на raw API + догрузка справочников).

Backend **не отдаёт** `allowed_actions` в `GET /api/v1/forms/{id}` — матрица CTA пока только на FE (`actions.ts`) с риском рассинхрона.

## A.5. Объём доработок — сводка

### Frontend (основной объём)

| Волна | Что | Оценка* | Результат |
|-------|-----|---------|-----------|
| **F0** | `lib/api`: client, JWT в sessionStorage `vdp-auth-v1`, 401/403, types | 2–3 дн | Можно логиниться |
| **F1** | Auth: `/login` → API; guard маршрутов; session provider | 1–2 дн | Реальная сессия |
| **F2** | `action-bridge.ts`: UI id → HTTP (actions + спец. endpoint'ы) | 4–6 дн | Кнопки бьют в core |
| **F3** | Mapper `Form` API ↔ UI; list + card `/forms`, `/forms/$id` | 4–5 дн | Реестр и карточка |
| **F4** | Create: `POST /forms` + `recognize_complete` + submit | 2–3 дн | Новая заявка в БД |
| **F5** | Files: upload, preview ACL, attach к form/order | 3–4 дн | Документы не fake |
| **F6** | Справочники: org, counterparty, provider (API вместо registry mock) | 4–6 дн | Реальные стороны сделки |
| **F7** | Manager: contract manual-attach, order generate, refund page | 4–5 дн | Расширенные вводные §2–4 |
| **F8** | Provider: `GET provider/forms` projection, без ПДн | 1–2 дн | Provider кабинет |
| **F9** | Admin/root, bank badge из `channel`, rating filters на API | 2–3 дн | Очереди менеджера |
| **F10** | Playwright на compose (real API), убрать/изолировать demo | 3–4 дн | Gate для UI |

\*Оценка: 1 dev, знакомый с кодовой базой; календарные дни, не спринты.

**Итого FE:**

- **MVP** (User → ICO → ECO → Manager → Provider → completed, без всех edge): **~18–25 дн**
- **Паритет с текущим демо-UI** (все экраны справочников, bulk, testing): **~30–40 дн**

### Backend (доработки под FE — меньше, но нужны)

| ID | Что | Зачем | Оценка |
|----|-----|-------|--------|
| **B1** | Опционально: `allowed_actions[]` в GET form | UI без дублирования `actions.ts` | 1–2 дн |
| **B2** | Опционально: alias `POST .../actions/accept_form` → submit | Упростить bridge | 0.5–1 дн |
| **B3** | List projection: `number`, org/cp names, channel badge | Меньше N+1 на FE | 2–3 дн |
| **B4** | Timeline/history endpoint или расширение GET form | UI хронология | 1–2 дн |
| **B5** | CORS только если FE без proxy (отдельный origin prod) | Деплой | 0.5 дн |

**Итого backend под FE:** **~3–8 дн** (B1–B3 желательны, не блокер MVP).

### Уже готово на backend (не переделывать)

- `POST /api/v1/auth/login`
- `GET/POST /api/v1/forms`, `POST .../actions/{action}`
- Files, contracts R3, refund, bank, multi-order
- Provider view + PII guard
- `make test`, `compose-e2e`, gate 331/331

## A.6. Рекомендуемый порядок (только FE track)

```
F0 → F1 → F3 (read) → F2 (actions) → F4 (create) → F5 (files)
→ smoke: compose User submit
→ F6 → F7 → F8 → F9 → F10
```

Параллельно backend: B3 (list enrichment) после F3, когда станет ясно, чего не хватает в JSON.

## A.7. Критерий «интеграция сделана» (DoD)

- [ ] Login через API, JWT в sessionStorage
- [ ] Список заявок с postgres seed, не mock
- [ ] Карточка: статус с сервера после каждого действия
- [ ] User: create → recognize_complete → submit
- [ ] Manager: assign provider + payment path (API e2e дублируется в браузере)
- [ ] Provider: только assigned, без полей ПДн
- [ ] Playwright ≥1 spec на real stack
- [ ] Demo/mock за feature flag или `/demo/*`, не смешан с prod path

**Не сделано:** OpenAPI для партнёра, staging bank, FE badge с API.

**Сделано:** адаптеры + CI contract tests.

**Не сделано:** prod/staging URLs; OCR = side-path (политика в known-gaps).
