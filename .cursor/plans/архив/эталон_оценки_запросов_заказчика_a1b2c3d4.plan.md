# Эталон оценки и планы под запросы заказчика

Опирается на [ориентир-скорости-запросов-заказчика-2026-09-21.md](../../заметки/ориентир-скорости-запросов-заказчика-2026-09-21.md). Старый LOC-ориентир 25.08 не трогаем кроме уже добавленной ссылки.

## Запрос заказчика (внутренний: процесс команды)

Специалист и агент оценивают и закрывают работу как **срез запроса роли**, а не как объём diff. Local QG и шаблон плана не дают сказать «готово» без Acceptance и имени gate.

## Acceptance

1. Новый план в `.cursor/plans` можно заполнить по шаблону за ≤ 10 минут (Запрос, Acceptance, слои, rules, DoD с gate).
2. В Local QG виден Callout про аксиому и ссылку на ориентир 21.09.
3. Новый человек по чеклисту поднимает hooks + env-parity и знает кнопку triage.

## Вне scope

- Правки домена заявки / платежей
- Новые GitHub jobs
- `release-gate` как ежедневная норма
- Пересчёт исторических LOC

## Слои

| Слой | Действие |
|---|---|
| UI / IA | Callout в Local QG canvas |
| FE продукт | Нет |
| Домен / API | Нет |
| Unit / E2E | Нет (процесс) |
| Docs / заметки | Шаблон + онбординг + таблица недели |
| Compose | Нет |

## Сверка с rules

Обязательны: `планирование-сверка-с-rules` (слои + QG в DoD с первой версии), `честность-готовности`, `vdp-ci-local-gate` (кнопки Local QG), `базовые-правила-инструмента`, `mgmt-tg-notify` вне scope этого плана.

Вне scope: `use-cases` статусов, `fe-interaction-contracts`, ML/serverless.

## DoD

1. Шаблон среза записан и на него ссылается ориентир 21.09 (или наоборот).
2. Callout в `local-qg.canvas.tsx` с аксиомой.
3. Чеклист онбординга доступен из заметки/how-to.
4. Таблица замера первой недели пустая, готова к заполнению вручную.
5. Gate на правки canvas/заметок: `make -C vdp check-env-parity` не обязателен для только-md; при правке только `local-qg.canvas.tsx` в корне — без `ci-pr`. Коммит по явной просьбе.

## Срезы дня (исполнение)

- День A: шаблон + ссылка из ориентира + таблица недели.
- День B: Callout Local QG + онбординг-чеклист.
