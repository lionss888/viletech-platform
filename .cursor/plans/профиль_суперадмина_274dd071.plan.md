# Профиль суперадмина (добавить в существующий план)

Текст ниже — новый раздел в [карточка_инвойс_агент_провайдер_5edd7203.plan.md](.cursor/plans/карточка_инвойс_агент_провайдер_5edd7203.plan.md). Отдельным планом не исполнять. Пункты 1–3 (инвойс, агент/провайдер, договор) не меняются.

## Как устроено сейчас

Меню в шапке ([VedAppShell.tsx](vdp/fe/src/components/ved/VedAppShell.tsx)): «Профиль» и «Настройки» оба открывают `/profile`. Страница ([profile-page.tsx](vdp/fe/src/components/ved/pages/profile-page.tsx)) — только Telegram и SMS. Имени, роли и места в системе на ней нет.

Root в сиде — `RoleRoot`, тип `admin`, без `organizationId` ([app-seed-accounts.ts](vdp/fe/src/lib/ved/app-seed-accounts.ts)). `GET /api/v1/account` уже отдаёт `full_name`, `email`, `role`. Поле организации у root пустое — это норма, не дыра данных.

## 4. Карточка профиля суперадмина

Только вошедший root, только чтение. Цель среза — показать каркас, по которому потом соберём карточки остальных ролей.

Порядок на экране (сначала суть, потом уже существующие уведомления):

- Имя: Root Admin
- Роль: Суперадмин
- Email: `root@vdp.local`
- Строка места: «Вне учётных записей»

Организацию не рисуем: ни селекта, ни прочерка. Прочерк выглядел бы как забытая привязка, а root вне учётных записей по правилу.

Telegram и SMS остаются ниже карточки. Подзаголовок страницы для root — «Суперадмин», не «Привязка Telegram и уведомления».

Для любой другой роли страница остаётся как сейчас (только уведомления). Карточку клиента, менеджера и провайдера и обязательную привязку к организации в этот срез не делаем.

«Настройки» по-прежнему открывают тот же `/profile`. Разведение профиля и настроек — следующий срез, не этот.

Домен и API не меняются. Root нельзя привязать к организации с этой страницы: `UpdateSelf` организацию и так не пишет.

## Слои этого среза

- UI: одна карточка сверху [profile-page.tsx](vdp/fe/src/components/ved/pages/profile-page.tsx). Маршрут `/profile` и `/demo/profile` уже есть.
- FE: чистая функция вида «роль root → поля карточки», без организации.
- Домен / API: без изменений. Статусы заявок не затрагиваются.
- Unit: FE на поля root и на то, что у не-root карточки нет.
- E2E: войти как root, открыть меню, кликнуть «Профиль», увидеть «Вне учётных записей» и не увидеть организацию. Спека вне узкого PR-smoke.
- Локальный repro: localhost, учётка `root@vdp.local`.

## Сверка с rules

К срезу обязательны: `ui-web-практики` и `ux-*` (сначала кто и роль, один термин), `безопасность-ролей-и-данных` (root вне организации; ПДн чужих пользователей на экран не выводить), `playwright-e2e`, `честность-готовности`, `vdp-ci-local-gate`.

Вне scope среза: привязка обычных пользователей к организации, карточки других ролей, отдельная страница «Настройки», правка справочника пользователей, документация, Telegram-уведомление менеджмента.

## DoD среза

1. `make -C vdp check-env-parity` до прогонов.
2. Unit FE на карточку root.
3. `make -C vdp ci-main` — новая e2e-спека профиля вне узкого smoke. `ci-pr` и `ci-pr-pilot` этот браузерный прогон не закрывают.
4. На localhost root открывает «Профиль» и видит имя, роль, email и «Вне учётных записей».

Пункты 1–3 плана по-прежнему закрываются `make -C vdp ci-pr-pilot`. Готовность всего файла — только после зелёного gate того среза, который реально меняли.
