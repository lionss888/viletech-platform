## Зелёная зона — можно реализовать сразу (бэкенд, ясный объём)

| № | Пункт из задач | Где править в fea-stage-vf2 | Что сделать |
|---|----------------|-----------------------------|-------------|
| 1 | **Счёт контрагента до 20 символов** (Клиент, п.1) | `src/modules/counterparty/dto/counterparty-account.dto.ts` | Добавить `@MaxLength(20)` для `accountNumber` в `AddAccountDto` + импорт `MaxLength` из `class-validator`. |
|   |   | `src/modules/counterparty/dto/counterparty.create.dto.ts` | Добавить `@MaxLength(20)` для `accountNumber` в `CounterpartyBankAccountDto`. |
|   |   | `src/modules/counterparty/service/counterparty.schema.ts` | Опционально: `@Prop({ required: true, index: true, maxlength: 20 })` у `CounterpartyBankAccount.accountNumber`. |
| 2 | **Поиск по контрагентам** (V-94) (Клиент, п.2) | `src/modules/counterparty/dto/counterparty.query.dto.ts` | Добавить поле `search?: string` (или `inn?: string`) для текстового поиска. |
|   |   | `src/modules/counterparty/service/counterparty.service.ts` | В методе списка (findByAccount / listForAccount) собрать фильтр по `name`, при наличии `search`/`inn` — по ним (regex или точное совпадение). |
| 3 | **Отчёт агента: название компании вместо «не указано»** (Менеджер) | `src/modules/form-payment/service/additional/generate-docs.service.ts` ~стр. 410 | Заменить `principalCompany: formPayment.clientOrganization || '(не указано)'` на `formPayment.organization?.name ?? formPayment.clientOrganization ?? '(не указано)'`. |
| 4 | **Права казначея: просмотр всех сделок** (Казначей) | `src/modules/form-payment/web/treasurer/form-payment-treasurer.controller.ts` ~стр. 79–82 | При пустом фильтре не подставлять дефолтные `baseQuery.statuses` (три статуса), чтобы казначей видел все сделки; либо добавить явный режим «все статусы» по согласованию с продуктом. |
| 5 | **Поиск у казначея** (как у менеджера) (Казначей) | Тот же контроллер + DTO | `FormPaymentAdminPaginateDto` уже наследует `FormPaymentQueryDto` с полями `search`, `uid`. Проверить, что эти поля попадают в `baseQuery` (через `model`) и реально используются в `this.service.find(baseQuery, paginate)`. При необходимости явно пробросить. |
| 6 | **Менеджер обязателен на этапе формирования поручения** (Общие, п.12) | `src/modules/form-payment` (сервис/контроллер менеджера) | При переходе на этап signing_order или при сохранении заявки на этом этапе добавить проверку: если нет `manager` — 400 с сообщением. Опционально: в DTO обновления заявки для этого этапа — `@IsNotEmpty()` для поля `manager`. |
| 7 | **Разделительный знак — точка по валютам** (Общие, п.11) | `src/lib/utils/helpers/number-format-utils.ts` | Сейчас `Intl.NumberFormat('ru-RU')` даёт запятую. Либо сменить локаль/опции на использование точки, либо отдавать константу/настройку «decimalSeparator: '.'» для фронта и форматировать на клиенте. |
| 8 | **Копирование ID сделки из списка** (Общие, п.6) | DTO ответа списка заявок | В `src/lib/dto/models/form-payment.dto.ts` уже есть `uid?: number` (стр. 774). Убедиться, что в ответах списка (пагинация) это поле заполняется и отдаётся клиенту для копирования. |
| 9 | **Архивация организаций провайдера** (V-69) (Провайдер) | `src/modules/organization/service/organization.schema.ts` | Добавить поле `archived?: boolean` (по умолчанию `false`) в схему Organization. В сервисах и API списка организаций провайдера фильтровать по `archived: false`, при необходимости — эндпоинт «включая архивные». |

## Жёлтая зона — можно начинать после быстрого уточнения

| № | Пункт из задач | Что уточнить | Что уже есть в fea-stage-vf2 |
|---|----------------|--------------|------------------------------|
| 10 | Уведомления при неполной заявке (какой пункт не введён; не давать отправлять без ТН ВЭД) (Клиент, п.7) | Список обязательных полей и тексты ошибок. | Валидация и этапы в `form-payment`, `hs-code`. Можно заложить структуру ответа с массивом незаполненных полей. |
| 11 | Подтягивание организации провайдера с последней сделки по контрагенту (Комплаенс) | Отдельный эндпоинт или только подстановка при создании заявки. | Данные по сделкам и контрагентам есть; запрос «последняя заявка по контрагенту + организация провайдера» — бэкенд. |
| 12 | Комментарии по проверенным контрагентам (6 мес; значок «проверяется автоматически») (Комплаенс) | Правила: когда ставится авто-проверка, как считается 6 месяцев. | В схеме контрагента есть `lastApprovalComment`, история статусов; можно добавить поля срока и флага авто-проверки. |
| 13 | Добавить поля в выгрузку заявок для 1С (наименование организации провайдера, банк, контрагент) (Интеграция 1С, п.2) | Подтверждение набора полей и формата с 1С. | Выгрузка заявок и структуры данных в сервисах form-payment; расширение полей — предсказуемый объём. |
| 14 | Даты завершения / подтверждения провайдером / выплаты казначеем (Общие, п.4–5) | Один «срок исполнения» или несколько полей по этапам. | В схеме/истории статусов можно добавить даты; нужно зафиксировать поля и переходы. |

## Красная зона — лучше не стартовать первыми (зависимости / неясный формат)

| Пункт из задач | Причина |
|----------------|--------|
| Запрос SWIFT-документа (VM-5) (Клиент, п.5) | Нет ясного формата (файл, статус, отдельный тип в системе). |
| Блок реквизитов санкционных банков (Комплаенс) | Нужен источник данных (справочник/API) и правила обновления. |
| Pre-compliance (VF-7 5), Менеджер привлечения (VF-5) | Новые роли и флоу; лучше после фиксации сценариев в продукте. |
| Флоу авансов/постоплаты с 1С (подтверждение казначеем, авто-переходы) (Казначей) | Зависимость от контракта и поведения 1С. |
| Передача id клиента и новых статусов в 1С (Интеграция 1С, п.4–5) | Завязано на контракт с 1С. |
| Корректировка отображения пп у клиента, выгрузка пп отдельно (Клиент, п.3) | Требует уточнения по фронту и сценариям выгрузки. |
| Считывание реквизитов с инвойса/контракта до выбора контрагента (Клиент, п.4) | Может затрагивать recognition и порядок шагов в UI. |
| Мультивалютные счета (V-95), мультироль, открытие в отдельном окне, ссылки на задачи | Часть — фронт/инфра; нужны уточнения. |

## Рекомендуемый порядок работ (ближайший спринт)

1. **Быстрые победы (1–2 дня)**  
   - Счёт контрагента до 20 символов (п.1).  
   - Отчёт агента: название компании (п.3).  
   - Копирование ID сделки (п.8) — проверка, что `uid` в ответах списка.

2. **Права и фильтры казначея (2–3 дня)**  
   - Просмотр всех сделок (п.4).  
   - Поиск у казначея (п.5).

3. **Контрагенты и организации**  
   - Поиск по контрагентам (п.2).  
   - Архивация организаций провайдера (п.9).

4. **Правила и валидация**  
   - Обязательный менеджер на этапе формирования поручения (п.6).  
   - Разделительный знак по валютам (п.7).
