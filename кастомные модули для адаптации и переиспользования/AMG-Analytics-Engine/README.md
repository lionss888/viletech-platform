# AMG Banking Core - Автоматизированная банковская система

Готовое к развёртыванию ядро АБС с интеграцией AI на основе PostgreSQL и Docker.

## ✨ Основные возможности

- **PostgreSQL 15** - основная база данных
- **pgAdmin** - веб-интерфейс управления БД
- **🤖 Ollama** - AI/LLM функции
- **Streamlit Dashboard** - аналитика и отчеты
- **Docker** - полная контейнеризация
- **AI-аналитика** - фрод-детекция, анализ транзакций

## Структура БД

### Таблица `clients`
- `id` - Уникальный идентификатор клиента (SERIAL PRIMARY KEY)
- `first_name` - Имя клиента (VARCHAR NOT NULL)
- `last_name` - Фамилия клиента (VARCHAR NOT NULL)
- `tax_id` - ИНН/налоговый номер (VARCHAR UNIQUE)
- `created_at` - Дата создания записи (TIMESTAMP DEFAULT)

### Таблица `accounts`
- `id` - Уникальный идентификатор счета (SERIAL PRIMARY KEY)
- `account_number` - Номер счета (VARCHAR UNIQUE NOT NULL)
- `client_id` - Ссылка на клиента (INTEGER REFERENCES clients(id))
- `type` - Тип счета (VARCHAR)
- `currency` - Валюта счета (VARCHAR)
- `balance` - Баланс счета (NUMERIC(15,2) DEFAULT 0, CHECK >= 0)
- `opened_date` - Дата открытия счета (DATE)
- `is_active` - Статус активности счета (BOOLEAN)

### Таблица `transactions`
- `id` - Уникальный идентификатор транзакции (BIGSERIAL PRIMARY KEY)
- `debit_account_id` - Счет списания (INTEGER REFERENCES accounts(id))
- `credit_account_id` - Счет зачисления (INTEGER REFERENCES accounts(id))
- `amount` - Сумма транзакции (NUMERIC(15,2) CHECK > 0)
- `currency` - Валюта транзакции (VARCHAR)
- `description` - Описание транзакции (TEXT)
- `status` - Статус транзакции (VARCHAR)
- `created_at` - Дата создания транзакции (TIMESTAMP)
- `executed_at` - Дата выполнения транзакции (TIMESTAMP)
- Ограничение: счета дебета и кредита должны быть разными

## Быстрый запуск

### 1. Подготовка
Скопируйте файл конфигурации:
```bash
cp config/environments/env.example config/environments/.env
```

### 2. Запуск системы

**Простой способ (Windows):**
```cmd
scripts\setup\start.bat
```

**Простой способ (macOS/Linux):**
```bash
chmod +x scripts/setup/start.sh
./scripts/setup/start.sh
```

**Ручной запуск:**
```bash
docker-compose up -d
```

**Остановка системы:**
```bash
./scripts/setup/stop.sh
```

**Тестирование системы:**
```bash
./scripts/setup/test_system.sh
```

### 3. Проверка работы
```bash
docker-compose ps
```

## Подключение к БД

После запуска вы можете подключиться к базе данных:

**Параметры подключения:**
- **Хост:** localhost
- **Порт:** 5432
- **База данных:** abs_core
- **Пользователь:** abs_user
- **Пароль:** значение из файла config/environments/.env

**Пример подключения через psql:**
```bash
psql -h localhost -p 5432 -U abs_user -d abs_core
```

## Доступ к веб-интерфейсам

### pgAdmin - управление базой данных
pgAdmin предоставляет удобный веб-интерфейс для управления базой данных.

### Аналитическая панель - визуализация данных
Streamlit дашборд для аналитики и отчетов.

### Вход в pgAdmin
1. После запуска откройте http://localhost:5050
2. Войдите с учетными данными из файла .env:
   - **Email:** admin@abs.local
   - **Пароль:** значение PGADMIN_DEFAULT_PASSWORD из файла .env

### Подключение к базе данных через pgAdmin
1. После входа нажмите "Add New Server"
2. На вкладке "General":
   - **Name:** ABS PostgreSQL
3. На вкладке "Connection":
   - **Host name/address:** postgres
   - **Port:** 5432
   - **Maintenance database:** abs_core
   - **Username:** abs_user
   - **Password:** значение DB_PASSWORD из файла .env
4. Нажмите "Save"

После подключения вы сможете:
- Просматривать структуру таблиц
- Выполнять SQL запросы
- Управлять данными через графический интерфейс
- Экспортировать и импортировать данные

Автоматически создаются индексы для оптимизации запросов по:
- ИНН клиентов
- Номерам счетов
- Статусам транзакций
- Датам создания транзакций

## Безопасность

### Учетная запись суперадминистратора
После первого запуска системы автоматически создается учетная запись владельца:
- **Логин:** lionss
- **Пароль:** lionss2025
- **Права:** Полный контроль над системой, включая:
  - Создание и удаление любых объектов БД
  - Управление всеми пользователями
  - Полный доступ ко всем данным
  - Эксклюзивное право на удаление записей

**ВАЖНО:** Обязательно смените пароль суперадминистратора после первого входа!

### Иерархия прав пользователей
Система использует уровни прав от 1 до 10:
- **Уровень 10:** Только суперадминистратор (владелец системы)
- **Уровень 6-9:** Администраторы (создаются только суперадминистратором)
- **Уровень 3-5:** Операторы
- **Уровень 1-2:** Пользователи с правами только на чтение

### Предустановленные роли
1. **abs_admin** - Администратор (может читать, добавлять, изменять, но НЕ удалять)
2. **abs_operator** - Оператор (ограниченные права на добавление и чтение)
3. **abs_readonly** - Только чтение всех данных

### Защитные механизмы
- Пароль БД хранится в отдельном файле .env
- Используется безопасный пароль с символами разного регистра, цифрами и спецсимволами
- Контейнер изолирован от основной системы
- Данные сохраняются в именованном Docker volume
- Включена политика безопасности на уровне строк (RLS)
- Автоматический аудит критических операций
- Защита от удаления учетной записи владельца
