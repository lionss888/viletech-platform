# Архитектура системы Вили (VILI)

## Обзор

**Вили (VILI)** — AI-ассистент для автоматизации документооборота международных платежей (традиционных и криптовалютных). Система сокращает время обработки платежей, повышает точность compliance-проверок и снижает операционные затраты за счёт адаптивного обучения на обратной связи операционистов.

**Ключевая особенность:** Вили работает **вместе со специалистом**, а не вместо него, помогая операционистам эффективнее коммуницировать с клиентами.

**Дата создания:** 2025-01-27  
**Версия:** 1.0

## Детальная архитектура компонентов

### 1. Integration Layer (Слой интеграции)

**Назначение:** Интеграция Вили в существующее приложение заказчика без зависимости от его технологического стека.

#### 1.1 JavaScript SDK
- **Функции:**
  - Widget компонент для встраивания в любое веб-приложение
  - Chat интерфейс для взаимодействия с ассистентом
  - API клиент для вызова функций Вили
  - Event system для коммуникации с приложением заказчика

- **Особенности:**
  - Работает в любом браузере
  - Не зависит от фреймворка заказчика
  - Изолированные стили (не конфликтуют с приложением)
  - Минимальный размер bundle

#### 1.2 Web Components
- **Функции:**
  - Custom Elements для встраивания в современные фреймворки
  - Shadow DOM для изоляции стилей
  - События для коммуникации

- **Особенности:**
  - Стандарт веб-платформы
  - Работает в React, Vue, Angular, Vanilla JS
  - Переиспользуемые компоненты

#### 1.3 REST API (Direct)
- **Функции:**
  - Прямой доступ к API для полного контроля
  - Поддержка любых языков программирования
  - Webhooks для уведомлений

- **Особенности:**
  - Максимальная гибкость
  - Заказчик создает свой UI
  - Подходит для backend интеграций

#### 1.4 API Gateway
- **Функции:**
  - CORS управление
  - Аутентификация и авторизация
  - Rate limiting
  - Request/Response трансформация

---

### 2. VILI Core (Ядро системы)

**Назначение:** Центральная бизнес-логика системы

#### 2.1 Workflow Manager
- Управление процессами обработки платежей
- Маршрутизация документов
- Приоритизация задач
- Управление очередями

#### 2.2 Document Processor
- Парсинг документов (PDF, XML, SWIFT, JSON)
- Нормализация данных
- Извлечение структурированной информации
- Валидация форматов

#### 2.3 Compliance Engine
- Проверка соответствия регулятивным требованиям
- Sanctions screening
- AML/KYC проверки
- Travel Rule enforcement (для крипто)

#### 2.4 Risk Assessment Engine
- Оценка рисков платежей
- Агрегация оценок от различных модулей
- Принятие решений на основе рисков
- Генерация рекомендаций

#### 2.5 Report Generator
- Генерация compliance отчетов
- SAR (Suspicious Activity Reports)
- Отчеты для операционистов
- Экспорт в различные форматы

#### 2.6 Adaptive Learning Module
- Сбор обратной связи от операционистов
- Обучение моделей на основе обратной связи
- Адаптация под специфику банка
- Персонализация под операциониста

#### 2.7 Communication Module
- Индикация статусов обработки
- Уведомления операционистов
- Визуализация рисков
- Рекомендации системы

---

### 3. AI Agents Layer (FinRobot)

**Назначение:** Интеллектуальные агенты для обработки задач

**Архитектура Perception-Brain-Action:**

#### 3.1 Perception Module
- **Захват данных:**
  - Документы платежей (традиционные)
  - Блокчейн транзакции (крипто)
  - Структурирование данных
  - Нормализация форматов

#### 3.2 Brain Module
- **Обработка через LLM:**
  - Использование FinGPT для анализа
  - Financial Chain-of-Thought (CoT)
  - Генерация структурированных инструкций
  - Принятие решений

#### 3.3 Action Module
- **Выполнение действий:**
  - Проверка compliance
  - Генерация отчетов
  - Уведомления
  - Блокировка/одобрение транзакций

#### 3.4 Smart Scheduler
- **Управление агентами:**
  - Director Agent (распределение задач)
  - Agent Registration (управление агентами)
  - Agent Adaptor (адаптация агентов)
  - Task Manager (управление задачами)

**Типы агентов:**

1. **Document Analysis Agent**
   - Анализ документов платежей
   - Извлечение ключевой информации
   - Валидация данных

2. **Compliance Agent**
   - Проверка compliance требований
   - Sanctions screening
   - AML/KYC проверки

3. **Risk Assessment Agent**
   - Оценка рисков через FinRL
   - Анализ паттернов
   - Генерация risk scores

4. **Blockchain Analysis Agent** (для крипто)
   - Анализ блокчейн транзакций
   - Выявление паттернов отмывания
   - Отслеживание адресов

5. **Report Generation Agent**
   - Генерация отчетов
   - Форматирование данных
   - Экспорт в различные форматы

### 4. LLM Layer (FinGPT)

**Назначение:** Анализ документов через языковые модели

**Компоненты:**

#### 4.1 Document Analysis Module
- **Модели:**
  - FinGPT v3.3 (Llama2-13B) для анализа настроений
  - Multi-task модели для комплексного анализа

- **Функции:**
  - Анализ тональности документов
  - Извлечение сущностей (бенефициар, отправитель, сумма)
  - Классификация документов
  - Извлечение отношений между сущностями

#### 4.2 Compliance Analysis Module
- **Функции:**
  - Анализ compliance документов
  - Проверка соответствия требованиям
  - Извлечение compliance данных
  - Генерация compliance отчетов

#### 4.3 Financial CoT Module
- **Функции:**
  - Структурированный анализ сложных документов
  - Разбиение задач на логические шаги
  - Логическое обоснование решений
  - Улучшенная интерпретируемость

#### 4.4 RAG Module (FinGPT-RAG)
- **Функции:**
  - Retrieval-Augmented Generation
  - Использование внешних знаний (регулятивы, санкции)
  - Контекстный анализ документов
  - Референс к историческим кейсам

## Модульность и расширяемость

### Plugin System

Система поддерживает модульную архитектуру с плагинами:

```python
# Псевдокод
class VILI_Plugin_System:
    def register_plugin(self, plugin):
        """Регистрация плагина"""
        self.plugins[plugin.name] = plugin
    
    def activate_plugin(self, plugin_name, conditions):
        """Условная активация плагина"""
        if self.check_conditions(conditions):
            return self.plugins[plugin_name].execute()
```

### Конфигурация модулей

```yaml
# config.yaml
core_modules:
  fingpt: enabled
  finrobot: enabled
  finrl: enabled

optional_modules:
  deepecon:
    enabled: true
    activation_criteria:
      min_amount: 100000
      high_risk_countries: true
      currency_volatility: true
  
  stata_mcp:
    enabled: false
    activation_criteria:
      statistical_analysis: true
```

## Безопасность и Compliance
