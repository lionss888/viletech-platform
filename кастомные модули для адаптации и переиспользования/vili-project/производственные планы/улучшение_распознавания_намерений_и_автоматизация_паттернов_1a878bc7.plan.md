# План работ: Улучшение распознавания намерений и автоматизация паттернов

## Этап 1: Текущая адаптация паттернов

### Проблема

Запрос "покажи мне список заявок" не распознается как `LIST_FORM_PAYMENTS` и попадает в обычный LLM-чат вместо использования интеграции с fea-stage.

### Решение

**1.1. Улучшение паттерна LIST_FORM_PAYMENTS**

Файл: `backend/app/services/intent_detector.py` (строки 76-83)

Изменения:

- Повысить приоритет с 6 до 9
- Добавить ключевые слова: "мне", "дай", "выведи", "отображ", "покажи"
- Упростить required_keywords (оставить только "заявк" или "платеж")

**1.2. Тестирование**

- Проверить распознавание запроса "покажи мне список заявок"
- Убедиться, что запрос маршрутизируется в `_handle_list_form_payments`
- Проверить работу интеграции с fea-stage

### 2.1. Система логирования запросов

**2.1.1. Создание таблицы для логов**

Файл: `backend/init.sql` (добавить после существующих таблиц)

Создать таблицу `intent_recognition_logs`:

- `id` (UUID, primary key)
- `message` (TEXT) - исходное сообщение пользователя
- `detected_intent` (VARCHAR) - распознанное намерение
- `confidence` (FLOAT) - уверенность распознавания
- `matched_pattern_id` (INTEGER) - ID паттерна, который сработал
- `all_matches` (JSONB) - все совпадения с уверенностью
- `entities` (JSONB) - извлеченные сущности
- `response_type` (VARCHAR) - тип ответа (handler/llm)
- `processing_time_ms` (INTEGER)
- `user_id` (UUID, nullable)
- `created_at` (TIMESTAMP)

**2.1.2. Создание схемы для логов**

Файл: `backend/app/database/schemas/intent_log.py` (новый файл)

Создать Pydantic модели:

- `IntentLog` - для записи логов
- `IntentLogCreate` - для создания записей
- `IntentLogResponse` - для ответов API

**2.1.3. Интеграция логирования в IntentDetector**

Файл: `backend/app/services/intent_detector.py`

Добавить метод `log_detection()`:

- Сохраняет результат распознавания в БД
- Логирует все совпадения паттернов (не только лучшее)
- Сохраняет метаданные для анализа

**2.1.4. Интеграция логирования в Chat API**

Файл: `backend/app/api/v1/chat.py`

В функции `send_chat_message()`:

- После распознавания намерения вызвать логирование
- Сохранить информацию о маршрутизации (какой handler использован)
- Сохранить время обработки

### 2.2. Анализатор паттернов (LLM-based)

**2.2.1. Создание сервиса анализа**

Файл: `backend/app/services/pattern_analyzer.py` (новый файл)

Класс `PatternAnalyzer`:

- Метод `analyze_low_confidence_requests()` - анализирует запросы с confidence < 0.7
- Метод `analyze_failed_patterns()` - анализирует запросы, попавшие в CHAT вместо специфичных intent'ов
- Метод `analyze_pattern_performance()` - анализирует эффективность каждого паттерна

**2.2.2. LLM-промпт для анализа**

Создать системный промпт для LLM:

- Анализирует примеры запросов
- Определяет, какие ключевые слова отсутствуют в паттернах
- Предлагает улучшения: новые keywords, изменения priority, изменения required_keywords

**2.2.3. Периодический анализ**

Файл: `backend/app/services/pattern_analyzer.py`

Метод `run_periodic_analysis()`:

- Собирает данные за последний период (по умолчанию 24 часа)
- Фильтрует запросы с низкой уверенностью или неправильным распознаванием
- Отправляет в LLM для анализа
- Получает предложения по улучшению

### 2.3. Генератор улучшений паттернов

**2.3.1. Создание сервиса оптимизации**

Файл: `backend/app/services/pattern_optimizer.py` (новый файл)

Класс `PatternOptimizer`:

- Метод `generate_improvements()` - генерирует улучшения на основе анализа LLM
- Метод `validate_improvement()` - проверяет корректность предложенного улучшения
- Метод `apply_improvement()` - применяет улучшение к паттерну

**2.3.2. Формат предложений улучшений**

Структура `PatternImprovement`:

- `pattern_intent` - IntentType
- `suggested_keywords` - список новых/измененных keywords
- `suggested_required_keywords` - изменения required_keywords
- `suggested_exclude_keywords` - изменения exclude_keywords
- `suggested_priority` - новый приоритет
- `confidence` - уверенность в улучшении
- `examples` - примеры запросов, которые будут лучше распознаваться

**2.3.3. Валидация улучшений**

Перед применением:

- Проверить, что улучшение не конфликтует с другими паттернами
- Проверить на тестовых данных
- Оценить влияние на другие паттерны

**2.4.3. API для управления паттернами**

Файл: `backend/app/api/v1/intent_patterns.py` (новый файл)

Endpoints:

- `GET /api/v1/intent-patterns` - список всех паттернов
- `GET /api/v1/intent-patterns/{intent_type}` - паттерн по типу
- `POST /api/v1/intent-patterns/analyze` - запустить анализ и получить предложения
- `POST /api/v1/intent-patterns/apply` - применить улучшения автоматически
- `GET /api/v1/intent-patterns/stats` - статистика эффективности паттернов

**2.4.4. Фоновый процесс автоматического улучшения**

Файл: `backend/app/services/pattern_auto_optimizer.py` (новый файл)

Класс `PatternAutoOptimizer`:

- Запускается по расписанию (например, раз в день через Celery или asyncio)
- Собирает данные за период
- Запускает анализ через `PatternAnalyzer`
- Генерирует улучшения через `PatternOptimizer`
- Автоматически применяет улучшения (согласно настройке пользователя)
- Логирует все изменения

**2.4.5. Интеграция с Celery (опционально)**

- Создать задачу `optimize_intent_patterns` для периодического запуска

Если Celery не используется:
