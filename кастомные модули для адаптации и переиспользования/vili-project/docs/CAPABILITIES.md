**Дата создания:** 2026-01-03  
**Версия:** 1.0

---

## 📋 Общее описание

**VILI (Ваш Интеллектуальный Личный Инспектор)** — это AI-ассистент для автоматизации документооборота международных платежей (традиционных и криптовалютных). Система работает **вместе со специалистом**, а не вместо него, помогая операционистам эффективнее коммуницировать с клиентами.

**Ключевая цель:** Сокращение времени обработки платежей, повышение точности compliance-проверок и снижение операционных затрат за счёт адаптивного обучения на обратной связи операционистов.

**Точность извлечения:** > 95%

## 🔧 Технические возможности

### AI/ML Архитектура

#### Гибридная LLM архитектура:
- **Ollama Cluster** (2 инстанса + Nginx LB)
  - Локальные модели для быстрых задач
  - Параллелизация запросов
  - Load balancing
- **TGI (FinGPT)**
  - Специализированные финансовые модели локально
  - FinGPT sentiment analysis
  - FinGPT forecasting
- **LiteLLM**
  - Унифицированный API для всех LLM
  - Автоматический routing
  - Fallback механизмы
- **Cloud Models**
  - GPT-4, Claude-3 (fallback для сложных случаев)
  - Оптимизация затрат

#### Доступные модели:

**Локальные (Ollama):**
- `llama3.2` - универсальная генерация
- `qwen2.5:7b` - русский язык и финансы
- `qwen2.5:3b` - компактная версия
- `nomic-embed-text` - embedding для RAG
- `mistral` - креативные задачи
- `phi3:mini` - быстрая генерация

**Финансовые (TGI):**
- `fingpt-sentiment` - анализ финансового sentiment
- `fingpt-forecaster` - прогнозирование

**Облачные (fallback):**
- `gpt-4` - сложные задачи
- `gpt-4-turbo` - оптимизированная версия
- `claude-3-sonnet` - альтернативный fallback
- `claude-3-opus` - максимальная точность

#### RAG (Retrieval-Augmented Generation):
- База знаний для compliance
- Контекстный анализ документов
- Референс к историческим кейсам
- Использование внешних знаний (регулятивы, санкции)
- FinGPT-RAG модуль

#### FinRobot (AI Agents):
- **Perception Module** - захват и структурирование данных
- **Brain Module** - обработка через LLM, Financial Chain-of-Thought
- **Action Module** - выполнение действий (проверки, отчеты)
- **Smart Scheduler** - управление агентами, распределение задач

**Типы агентов:**
1. Document Analysis Agent
2. Compliance Agent
3. Risk Assessment Agent
4. Blockchain Analysis Agent (для крипто)
5. Report Generation Agent

#### FinRL (Reinforcement Learning):
- Risk Assessment Agent - оценка рисков с адаптивным обучением
- Workflow Optimization Agent - оптимизация последовательности проверок
- Pattern Detection Agent - выявление паттернов отмывания

## 🔌 API возможности

### Основные endpoints

#### 1. Documents API
- `POST /api/v1/documents/upload` - Загрузка документа
- `POST /api/v1/documents/{document_id}/analyze` - Анализ документа
- `GET /api/v1/documents/` - Список документов
- `GET /api/v1/documents/{document_id}` - Получить документ
- `DELETE /api/v1/documents/{document_id}` - Удалить документ
- `GET /api/v1/documents/{document_id}/analysis` - Результаты анализа

#### 2. Compliance API
- `POST /api/v1/compliance/check` - Запустить проверку
- `GET /api/v1/compliance/{document_id}` - Получить результаты проверок
- `GET /api/v1/compliance/statistics` - Статистика compliance

**Типы проверок:**
- `sanctions` - Проверка санкционных списков
- `kyc` - Know Your Customer
- `aml` - Anti Money Laundering
- `travel_rule` - Travel Rule compliance
- `fatf` - FATF требования

#### 3. Risk API
- `POST /api/v1/risk/assess` - Оценить риски
- `GET /api/v1/risk/{document_id}` - Получить оценку рисков
- `GET /api/v1/risk/{document_id}/history` - История оценок
- `GET /api/v1/risk/statistics` - Статистика рисков
- `GET /api/v1/risk/economic-indices/{country_code}` - Экономические индексы

#### 4. Knowledge Sources API
- `GET /api/v1/knowledge-sources/` - Список источников знаний
- `POST /api/v1/knowledge-sources/` - Создать источник знаний
- `GET /api/v1/knowledge-sources/{id}` - Получить источник
- `PUT /api/v1/knowledge-sources/{id}` - Обновить источник
- `DELETE /api/v1/knowledge-sources/{id}` - Удалить источник
- `POST /api/v1/knowledge-sources/{id}/refresh` - Обновить базу знаний
- `POST /api/v1/knowledge-sources/upload` - Загрузить документы
- `GET /api/v1/knowledge-sources/{id}/chunks` - Получить чанки

#### 5. Chat API
- `POST /api/v1/chat/message` - Отправить сообщение в чат
- `GET /api/v1/chat/intents` - Список доступных намерений
- `GET /api/v1/chat/models` - Список доступных моделей

#### 6. Operators API
- Управление операционистами
- Персонализация под операциониста
- Сбор обратной связи

#### 7. Intent Patterns API
- Управление паттернами намерений
- Оптимизация паттернов
- Автоматическая оптимизация

#### 8. Health & Feedback API
- `GET /api/v1/health` - Проверка здоровья системы
- `GET /api/v1/health/detailed` - Детальная проверка
- `POST /api/v1/feedback` - Отправить обратную связь
- `GET /api/v1/feedback` - Получить обратную связь

- ⚠️ Рекомендуется GPU для LLM

### Известные ограничения:

1. **Chat API - медленные ответы (60+ секунд)**
   - Причина: CPU режим, модель загружается в память при первом запросе
   - Решение: Нормально для CPU. Для продакшена нужен GPU
   - Статус: ⚠️ Работает, но медленно

2. **TGI (FinGPT) - не запущен по умолчанию**
   - Причина: Требует много ресурсов (10-15GB RAM), загрузка 10-15 минут
   - Решение: Опционально, не блокирует работу
   - Статус: ℹ️ Опционально

3. **LiteLLM - unhealthy статус в Docker**
   - Причина: Healthcheck может не проходить сразу после запуска
   - Решение: Сервис работает, но healthcheck требует времени
   - Статус: ⚠️ Работает, но требует проверки

## 🚀 Рекомендации по использованию

### Для разработки:
```bash
# Используйте локальный запуск
./start-local.sh

# Или вручную:
docker compose up -d postgres redis  # Только БД
cd backend && uvicorn app.main:app --reload  # Backend локально
```

**Преимущества:**
- Быстрая разработка
- Hot reload
- Легкая отладка

### Для продакшена:
```bash
# Используйте Docker запуск
./start-docker.sh

# Или
make start
```

**Преимущества:**
- Полная изоляция
- Готово для продакшена
- Воспроизводимая среда

### Проверка статуса:
```bash
# Локально
curl http://localhost:8000/api/v1/health

# Docker
make status
docker compose ps
```

### Требования для продакшена:
- **RAM:** 16GB+ (рекомендуется 32GB)
- **Диск:** 50GB+ свободного места
- **GPU:** Рекомендуется для оптимальной производительности LLM
