## Как использовать документацию

### Для начала работы

1. Прочитайте **README.md** для общего понимания проекта
2. Изучите **NEIMING.md** для контекста проекта
3. Ознакомьтесь с **ARCHITECTURE.md** для понимания архитектуры

### Для разработки

1. **REQUIREMENTS.md** - понимание требований
2. **TECHNICAL_SPECS.md** - технические детали
3. **PROJECT_STRUCTURE.md** - структура проекта
4. **IMPLEMENTATION_PLAN.md** - план работы

### Для интеграции

1. **INTEGRATION.md** - детальное руководство по интеграции
2. Примеры кода в **INTEGRATION.md**
3. API документация в **TECHNICAL_SPECS.md**

### Для планирования

1. **IMPLEMENTATION_PLAN.md** - детальный план реализации
2. **REQUIREMENTS.md** - приоритизация требований
3. **ARCHITECTURE.md** - архитектурные решения

## Обновление документации

Документация должна обновляться при:

- Изменении архитектуры
- Добавлении новых требований
- Изменении плана реализации
- Обновлении технических спецификаций
- Добавлении новых способов интеграции

---

## Версионирование документации

Все документы имеют версию в заголовке. При значительных изменениях версия должна быть обновлена.

**Формат версии:** MAJOR.MINOR

- **MAJOR** - значительные изменения архитектуры или требований
- **MINOR** - добавление деталей, исправления, уточнения
