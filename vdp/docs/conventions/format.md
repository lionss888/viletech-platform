# Формат документации VDP

Правило распространяется на vdp/README.md и все markdown-файлы в каталоге vdp/docs. Не распространяется на .cursor/plans, rd0-baseline.md и заметки вне vdp.

## Разрешённые элементы

Заголовок h1 — один на документ, название страницы.

Заголовок h2 — основной раздел.

Заголовок h3 — подраздел внутри h2.

Абзац p — основной текст, включая структурированные данные и ссылки.

## Запрещённые элементы

Markdown-таблицы с вертикальными чертами.

Маркированные и нумерованные списки.

Чекбоксы и task-листы.

Bold, italic, strike.

Horizontal rule.

Blockquote.

Mermaid и ASCII-диаграммы.

Emoji и декоративные символы.

HTML-теги для оформления.

Заголовки h4 и ниже.

Backtick-fences и inline backticks вне исключения для development.

## Структурированные данные

Табличные и перечисляемые данные передаются серией абзацев с явной микроструктурой в тексте.

Пример допустимого фрагмента.

Поле DATABASE_URL_CORE. Значение postgres://vdp_core:vdp_core@localhost:5432/vdp_core. Назначение подключение core к Postgres в dev.

Пример недопустимого фрагмента.

Таблица env vars или три пункта с дефисом в начале строки.

## Исключение для shell-команд

Только в vdp/docs/development/*.md допускаются fenced code blocks для многострочных команд терминала. Во всех остальных разделах команды и пути пишутся внутри абзацев обычным текстом.

## Ссылки

Гиперссылки на другие документы и исходники допустимы внутри абзацев стандартным markdown-синтаксисом ссылки.

## Проверка

Команда make docs-format-check в каталоге vdp проверяет соблюдение правила автоматически.
