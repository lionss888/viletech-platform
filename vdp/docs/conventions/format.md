# Как оформляять документацию

Эти правила действуют для всех файлов в папке vdp/docs и для файла vdp/README.md. Планы работ, служебные заметки и файлы вне vdp под это правило не подпадают.

## Что можно использовать

Заголовок первого уровня — только один на страницу для названия.

Заголовки второго уровня — для основных разделов.

Заголовки третьего уровня — для подразделов внутри основных.

Обычные абзацы — для всего остального текста, включая технические данные и ссылки.

## Что нельзя использовать

Таблицы с вертикальными чертами.

Любые списки — ни маркированные, ни нумерованные.

Чекбоксы и списки задач.

Выделение жирным, курсивом или зачёркиванием.

Горизонтальные линии.

Цитаты (блокквоты).

Диаграммы — ни Mermaid, ни ASCII-графика.

Эмодзи и украшательства.

HTML-теги для оформления.

Заголовки четвёртого уровня и глубже.

Блоки кода и backtick'и (кроме специального случая для development).

## Структурированные данные

Табличные и перечисляемые данные передаются серией абзацев с явной микроструктурой в тексте.

Пример допустимого фрагмента.

Поле DATABASE_URL_CORE. Значение postgres://vdp_core:vdp_core@localhost:5432/vdp_core. Назначение подключение core к Postgres в dev.

Пример недопустимого фрагмента.

Таблица env vars или три пункта с дефисом в начале строки.

## Особый случай для команд терминала

Только в файлах vdp/docs/development/ можно использовать блоки кода для длинных команд терминала. Везде остальных местах команды пишутся обычным текстом внутри абзацев.

## Ссылки между документами

Обычные markdown-ссылки на другие файлы документации разрешены в любом месте абзаца.

## Автоматическая проверка

Команда make docs-format-check в папке vdp проверяет, что все документы соответствуют этим правилам.
