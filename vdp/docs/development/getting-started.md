# Как начать работать с VDP

## Что нужно установить

Для запуска всей системы достаточно Docker и Docker Compose. 

Если хотите запускать компоненты по отдельности, понадобится Go 1.22+, Node.js с npm (или Bun) и PostgreSQL 16.

## Запуск всей системы

```sh
cd vdp
make compose-up
```

После того как всё поднимется, откроется интерфейс на http://localhost:5173, API на http://localhost:8080 и Hub на http://localhost:8081. Автоматически запустится небольшой тест, чтобы проверить, что всё работает.

### Пересборка фронта в Docker (спросить перед запуском)

`fe` в compose монтирует исходники, но зависимости лежат в volume `fe_node_modules`. После первого старта, смены ветки, `git pull` или sync UI (в т.ч. Lovable) **спроси себя / агента**, нужно ли обновить зависимости:

```sh
make compose-fe-refresh
```

Команда спросит подтверждение (`y/N`). Без вопросов: `FE_REFRESH=1 make compose-fe-refresh` или `./scripts/compose-fe-refresh.sh --yes`.

Если на http://localhost:5173 приходит 500 с `Cannot find module …` — почти всегда нужен именно этот refresh, а не только `docker compose up --build`.

## Если нужен только фронтенд

```sh
cd vdp/fe
npm i
npm run dev
```

По умолчанию API-запросы идут на localhost:8080. Можно изменить это через переменную VDP_API_PROXY_TARGET или запустить бэкенд отдельно.

## Тестовые аккаунты

Все аккаунты используют формат роль@vdp.local с паролем как название роли.

Пользователь: user@vdp.local, пароль user, ID 11111111-1111-1111-1111-111111111111.

Менеджер: manager@vdp.local, пароль manager, ID 22222222-2222-2222-2222-222222222222.

Внутренний комплаенс: ico@vdp.local, пароль ico, ID 33333333-3333-3333-3333-333333333333.

Внешний комплаенс: eco@vdp.local, пароль eco, ID 44444444-4444-4444-4444-444444444444.

Провайдер платежей: provider@vdp.local, пароль provider, ID 55555555-5555-5555-5555-555555555555.

Банк: bank@vdp.local, пароль bank, ID 77777777-7777-7777-7777-777777777777.

Администратор: root@vdp.local, пароль root, ID 99999999-9999-9999-9999-999999999999.

Тестовая организация называется "ООО Пример" с ID 66666666-6666-6666-6666-666666666666.

Для банковского API используется отдельная организация с ID 88888888-8888-8888-8888-888888888888.

## Демо-режим

Есть специальные URL вида /demo/*, которые работают с локальными заглушками данных. Для демо используйте аккаунты user@demo.vdp.local и так далее.

Важно: демо-режим не связан с настоящей базой данных. Подробнее читайте в [app-vs-demo.md](../architecture/app-vs-demo.md).

## Примеры API-запросов

Как получить JWT-токен:

```sh
curl -sf -X POST http://127.0.0.1:8080/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"user@vdp.local","password":"user"}'
```

Проверить здоровье системы:

```sh
curl -sf http://127.0.0.1:8080/api/v1/health
```

## Обновление веток

После `git pull` / смены ветки / sync в `vdp/fe` снова решите, нужен ли refresh зависимостей в Docker:

```sh
cd vdp
make compose-fe-refresh
```

Не полагайтесь только на host `npm install`: volume контейнера от этого не обновится.

## Если что-то пошло не так

Система не поднимается после `make compose-up`: проверьте `docker compose ps`, убедитесь что порты 5173, 8080, 8081 свободны, попробуйте запустить заново. Для 500 на фронте — `make compose-fe-refresh`.

Ошибка 403 при создании заявки через банковский API: используйте правильный ID организации 88888888-8888-8888-8888-888888888888, а не обычный пользовательский.

Playwright не устанавливается на macOS: используйте `make playwright-e2e` вместо `npx playwright install` — команда запустит тесты в Docker.
