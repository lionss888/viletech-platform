## Executive Summary

FE unit tests failed in GitHub Actions CI with cryptic Vite Vitest errors this.bridge.setTestsError is not a function rolldown bindings errors. Root cause Node.js version mismatch between local environment v22.17.0 and CI v20 hardcoded in workflow. Native modules built for Node.js 22 were incompatible with Node.js 20 runtime in CI.

## Root Cause

Primary Cause hardcoded Node.js version in CI workflow node-version 20 diverged from local environment Node.js 22.17.0. No mechanism to enforce version parity or catch divergence before CI run.

Contributing Factors no .nvmrc file Node.js version was not pinned in repository. No environment parity checks pre-commit hooks and CI did not verify version consistency. Cryptic error messages native module failures in Vite Vitest appeared as internal framework errors obscuring root cause. Agent overconfidence agent claimed ready without running full local CI gate ci-pr before push. Lack of environment documentation no canonical source for required versions. No systematic prevention rules existed but did not include environment parity enforcement.

## Prevention Measures Implemented

.nvmrc single source of truth for Node.js version
CI env-parity job fail-fast if .nvmrc missing or not used in workflow
Pre-commit hook local version check before commit
make check-env-parity explicit command for developer self-check
Documentation canonical environment requirements in docs/development

## Lessons Learned

Never claim ready without running make ci-pr
Environment check is first gate before any commit verify versions match
Postmortem discipline every unexpected failure gets a postmortem not just a fix

Native modules are fragile version mismatches cause cryptic errors far from root cause
Hardcoded versions in CI are dangerous use version files .nvmrc .go-version etc
Early detection is cheaper than late debugging pre-commit checks save CI time

Trust requires verification ready claims must be backed by green gates
Systematic prevention is better than reactive fixes each incident should trigger lasting improvements
Documentation is infrastructure without canonical environment docs divergence is inevitable

Agent DoD must be enforced agent must run ci-pr before claiming ready not just unit tests
Rules alone are insufficient need automated checks to enforce rules
Overconfidence is costly each false ready claim erodes user trust
