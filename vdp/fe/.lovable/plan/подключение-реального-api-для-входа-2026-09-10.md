# Подключение реального API для входа

## Что я проверил

Ваш сервис `https://alpha.vedy.io` отвечает и вход работает: запрос с логином
`user@vdp.local` вернул успешный ответ с данными аккаунта (Ivan Petrov, роль «клиент»).
То есть API живой и доступен извне.

Проблема в другом: сейчас приложение отправляет запросы «в само себя»
(адрес по умолчанию — локальный компьютер), поэтому в превью вход падает с ошибкой 403.
Плюс ваш сервер не разрешает браузеру обращаться к нему напрямую с чужого домена,
поэтому запросы должны идти через сервер самого приложения.

## Что сделаю

1. Настрою приложение так, чтобы все обращения к API уходили на `https://alpha.vedy.io`
   через сервер приложения — и в превью, и в опубликованной версии.
2. Адрес останется настраиваемым: если позже появится другой сервер (прод, тест),
   его можно будет указать без переписывания кода.
3. Проверю живой вход на странице `/login` тестовыми учётными записями
   (`user@vdp.local`, `root@vdp.local`) и убедлюсь, что после входа открывается рабочий
   стол с данными из вашего сервиса, а раздел «Состояние платформы» больше не даёт 403.

Демо-контур (`/demo/*`) остаётся как есть — на моках, без обращения к серверу.

## Технические детали

- `vite.config.ts`: значение по умолчанию для `VDP_API_PROXY_TARGET` меняется с
  `http://localhost:8080` на `https://alpha.vedy.io`; прокси `/api` сохраняется для
  dev, preview и nitro `routeRules` (`/api/** → <target>/api/**`), `changeOrigin: true`.
- Прямой вызов из браузера не используется: у ответа `alpha.vedy.io` нет заголовков
  CORS (`Access-Control-Allow-Origin` отсутствует), поэтому `VITE_API_BASE_URL`
  остаётся пустым и `apiFetch` работает по относительным путям через прокси.
- Ничего в `src/lib/api/*`, `src/lib/auth/session.tsx` и в контуре `/demo` не меняется.
- Проверка: Playwright-прогон `/login` → `/dashboard` под `user@vdp.local` и
  `root@vdp.local`, плюс контроль сетевых ответов `/api/v1/auth/login`,
  `/api/v1/account`, `/api/v1/admin/platform-health`.
